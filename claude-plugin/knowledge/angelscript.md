# Angelscript (Hazelight UE Fork) — Knowledge Reference

This file is loaded by `studio:programming` when AS work surfaces, and by the `angelscript-code` path-scoped rule when editing `.as` files. It is reference material — patterns, gotchas, idioms — not a tutorial. The canonical sources listed in frontmatter are authoritative; this file mirrors them.

> **AI training-data warning.** AI models have near-zero AS training data. Every AS code suggestion you read here or write yourself should be validated against the canonical sources or hot-reload-tested in editor. The "AI Blind Spots" table below catches the most common confident-but-wrong patterns.

## When this knowledge applies

Angelscript is Hazelight's source-built UE5 fork that adds first-class scripting via the AngelScript language with deep UE bindings. It is distinct from vanilla UE5 (C++ + Blueprint) and from custom UE plugins. Code lives in `.as` files; classes registered via `UCLASS`/`UFUNCTION`/`UPROPERTY` macros are first-class UObjects from UE's perspective.

## AI Blind Spots (read this first)

The most common confident-but-wrong patterns. **Check every AS code snippet against this table.**

| AI will do (WRONG) | Correct AngelScript |
|---|---|
| `Actor->SetTransform()` (pointer syntax) | `Actor.SetTransform()` (dot notation, no pointers) |
| Generate `.h` + `.cpp` files | Single-file `.as` classes only |
| Write constructors | Use `default` keyword: `default Comp.Height = 88.0;` |
| Assume `float` is 32-bit | `float` is **64-bit double**; use `float32` or `0.0f` literals when interfacing with float32 APIs |
| Add `BlueprintType` to UCLASS | **`BlueprintType` is NOT valid in AS** — implicit when class is UObject derivative |
| Add redundant UPROPERTY specifiers | `EditAnywhere` + `BlueprintReadWrite` are defaults — omit them |
| Override `BeginPlay()` without decorator | Requires `UFUNCTION(BlueprintOverride)` |
| Use raw pointer syntax (`*`, `->`) | AS has no raw pointers; use dot notation |
| Write `#include` statements | AS uses `import` for cross-file references |
| Write `FString::Printf()` | Use format strings: `f"Value is {MyVar}"` |
| Declare `DECLARE_DYNAMIC_DELEGATE()` macros | Use `delegate` keyword: `delegate void FMyDelegate(float Value);` |
| Declare `DECLARE_DYNAMIC_MULTICAST_DELEGATE()` | Use `event` keyword: `event void FMyEvent(float Value);` |
| Assume C++ style casts | Use `Cast<T>(Object)` — same name but AS syntax |
| Declare `static UFoo Get(...)` on subsystem | **AS rejects user-declared `static` member functions.** Subsystem `::Get(WorldContext)` is auto-generated by the AS binding layer |
| Nest containers — `TMap<FName, TArray<...>>` | **AS rejects nested containers.** Use a wrapper struct or parallel flat arrays |
| Call `Super::Method()` in BlueprintOverride | **AS does NOT provide `Super` namespace.** Override the body; parent invocation is implicit |
| Use `FMath::Clamp` | Use `Math::Clamp` — Hazelight renames `FMath::*` → `Math::*` |
| Use `UWorld.SpawnActor(Class::StaticClass(), ...)` | Use global `SpawnActor(Class, Loc, Rot)` — class as value, not StaticClass() |
| Subclass `UGameInstanceSubsystem` (bare engine class) | Subclass `UScriptGameInstanceSubsystem` — `BlueprintOverride` on `Initialize`/`Deinitialize` requires the script wrapper, not the bare engine class |

## File and class structure

- One primary class per `.as` file. File name matches the primary class name without the type prefix: `EventBus.as` → `class UEventBus`.
- Files live under `<Project>/Script/...`. Subfolder convention mirrors namespace intent (`Script/Subsystems/`, `Script/Components/`, `Script/Actors/`, `Script/Data/`).
- Classes use UE prefixes: `U` for UObject-derived, `A` for AActor-derived, `F` for plain structs, `E` for enums, `I` for interfaces.
- Classes declare inheritance with `:`: `class UEventBus : UScriptGameInstanceSubsystem`. (For subsystems, use the `UScript*Subsystem` script wrapper — see §Subsystems below for the rule and rationale.)

## Type system essentials

| AS type | Notes |
|---|---|
| `float` | **64-bit double.** Use `float32` for 32-bit, OR use `0.0f` literal suffix for float32 literals |
| `float32` | 32-bit float (use when interfacing with engine APIs expecting float) |
| `float64` | Explicit double — same as `float` |
| `int` / `int32` | Signed 32-bit |
| `int64` | Signed 64-bit |
| `bool`, `uint8`, `uint16`, `uint32`, `uint64` | As expected |
| `FString` | Standard string type |
| `FName` | Use `n"LiteralName"` syntax for compile-time resolved FNames. Compare with `==`. `IsNone()` to test empty |
| `FText` | Localized text |
| `TArray<T>` | Dynamic array. `Add`, `Remove`, `Num`, `Contains`, `[i]`. `IsValidIndex(i)` to bounds-check |
| `TMap<K, V>` | Hash map. `Add`, `Contains`, `Remove`, `Num`, `[key]`. **Cannot nest** — `TMap<K, TArray<V>>` rejected |
| `TSet<T>` | Hash set |
| `FVector` / `FRotator` / `FQuat` | UE math types — standard |

`nullptr` is the null literal for UObject types. AS has no general null pointer.

## Float-default landmine

> **Most painful AS-specific gotcha.** A `float` declaration in script is a 64-bit double. Function-overload resolution picks based on this.

```as
// ❌ WRONG — Math::Clamp picks the float64 overload, but Bars.Happiness is float32
Bars.Happiness = Math::Clamp(Bars.Happiness - HappRate * Seconds, 0.0, 1.0);

// ✅ RIGHT — float literals match the float32 input
Bars.Happiness = Math::Clamp(Bars.Happiness - HappRate * Seconds, 0.0f, 1.0f);
```

Always use `0.0f` / `1.0f` literals when working with float32 fields. Mixing `float32` member fields with `0.0` (float64) literals will fail signature lookups in `Math::Clamp`, `Math::Min`, etc.

## Class declaration patterns

```as
// ✅ RIGHT — no BlueprintType (implicit), no constructors (use default)
UCLASS(Abstract)
class UCozyEvent : UObject
{
    UPROPERTY(BlueprintReadOnly)
    FName EventType;

    default EventType = n"";   // initializer via default keyword
}
```

Common `UCLASS` keywords (Hazelight AS valid set):
- `Abstract` — class can't be instantiated directly
- `Blueprintable` — Blueprints can subclass it
- `NotBlueprintable` — opt out of BP subclassing
- `NotPlaceable` — class can't be placed in editor world
- `Transient` — not serialized
- `HideDropdown` — hides class from UE dropdowns
- `DefaultToInstanced` — instances marked instanced by default
- `EditInlineNew` — instances editable inline in details panel
- `Deprecated` — marks class deprecated
- `Config` — class supports config-file properties
- `ClassGroup` — editor categorization
- `HideCategories` — hide property categories in details
- `DefaultConfig` — config saves to defaults
- `ComponentWrapperClass` — wrapper marker
- `Meta=(...)` — metadata key-value pairs

`BlueprintType` is **NOT** in this set. UE C++ uses it; AS makes it implicit.

## Property declarations

```as
// Default is EditAnywhere + BlueprintReadWrite — most cases need nothing more
UPROPERTY()
float DispatchTimeoutSeconds = 0.5f;

// Restrict explicitly when you don't want full exposure
UPROPERTY(BlueprintReadOnly)
FName EventType;

UPROPERTY(EditDefaultsOnly, Category = "Cozy|Tuning")
float MaxRecursionDepth = 8.0f;

UPROPERTY(VisibleAnywhere)
int CurrentRecursionDepth = 0;

// Cannot nest containers — wrap in a struct
struct FSubscriberList { TArray<FCozyEventDelegate> Callbacks; }
UPROPERTY()
TMap<FName, FSubscriberList> Subscribers;   // ✅ wrapped struct
// UPROPERTY() TMap<FName, TArray<FCozyEventDelegate>> Subscribers;  // ❌ nested — rejected
```

Common `UPROPERTY` keywords:
- `EditAnywhere` / `EditDefaultsOnly` / `EditInstanceOnly` — editor visibility
- `BlueprintReadOnly` / `BlueprintReadWrite` — Blueprint access level
- `VisibleAnywhere` — read-only in editor
- `NotEditable` — not visible in editor details
- `Category = "Foo|Bar"` — organizes the details panel; pipes denote nesting
- `Replicated` / `ReplicatedUsing=OnRep_X` — replication; pair with `OnRep_*` callbacks
- `SaveGame` — included in save-game serialization
- `Transient` — excluded from serialization
- `Meta = (ClampMin = 0)` — value constraints

`private` and `protected` are AS-language visibility keywords; they enforce visibility within the class but do NOT remove Blueprint exposure if `BlueprintReadOnly` is also set.

## Function declarations

```as
UFUNCTION(BlueprintCallable)
void Subscribe(FName EventType, FCozyEventDelegate Callback) { /* ... */ }

UFUNCTION(BlueprintOverride)   // overrides UE virtual — no Super:: call
void Initialize(FSubsystemCollectionBase& Collection) { /* setup */ }

UFUNCTION(BlueprintPure)
int GetCurrentRecursionDepth() const { return CurrentRecursionDepth; }

// Script-only — no UFUNCTION; faster hot-reload (no UE reflection update)
void InternalHelper() { /* ... */ }
```

Common `UFUNCTION` keywords:
- `BlueprintCallable` — invokable from BP graphs (default for `UFUNCTION()`)
- `BlueprintOverride` — overrides a UE virtual method (BeginPlay, Tick, Initialize, Deinitialize, etc.). **Body only — no `Super::Method()` call**
- `BlueprintPure` — node has no exec pin; treated as a pure expression. Avoid for side-effecting functions
- `BlueprintEvent` — new overridable event for child Blueprints (declares default body)
- `BlueprintImplementableEvent` — declared in AS, implemented in BP
- `Server` / `Client` / `NetMulticast` + (`Reliable` / `Unreliable`) — RPC. **AS defaults to reliable**; mark `Unreliable` explicitly
- `Category = "Foo"` — node placement in Blueprint context menus

**Rule:** Functions used in delegates, events, timers, and binding callbacks **must** be `UFUNCTION()`.

## `default` keyword (no constructors)

> *"Instead of using object constructors, which can run at unpredictable times during hot reloads, any default values for properties should be specified in the class body."* — Hazelight docs

```as
// ❌ WRONG — no constructors in AS
class ASquirrel : AActor
{
    ASquirrel() { Bars.Happiness = 1.0f; }
}

// ✅ RIGHT — default keyword
class ASquirrel : AActor
{
    UPROPERTY() FSquirrelBars Bars;
    default Bars.Happiness = 1.0f;
}
```

`default` also sets class-default values inherited from the parent:

```as
class ABackyardGameMode : AGameModeBase
{
    default PlayerControllerClass = ACozyPlayerController;
    default bReplicates = true;
    default Tags.Add(n"Cozy");
}
```

## Subsystems

### AS parent class — use the script wrapper, not the bare engine class

> **Common trap.** AS subsystem classes **must inherit from the `UScript*Subsystem` helper, not the bare engine class** — otherwise `BlueprintOverride` on `Initialize` / `Deinitialize` will fail to bind. The bare `UGameInstanceSubsystem` etc. declare `Initialize` as a plain virtual; the BIE hooks (`BP_Initialize` / `BP_Deinitialize`) live only on the script wrapper. AS resolves `Initialize` → `BP_Initialize` via prefix-strip, so the override method name stays plain.

| Subsystem kind | AS parent class | `::Get(...)` arg |
|---|---|---|
| GameInstance | `UScriptGameInstanceSubsystem` | any UObject |
| World | `UScriptWorldSubsystem` | WorldContextObject |
| LocalPlayer | `UScriptLocalPlayerSubsystem` | relevant player |
| Editor | `UScriptEditorSubsystem` | n/a (editor-only) |
| Engine | `UScriptEngineSubsystem` | n/a (engine lifetime) |

Inheriting from the bare engine class (`UGameInstanceSubsystem` etc.) compiles AS code "syntactically" but every `BlueprintOverride` on `Initialize` / `Deinitialize` produces:

```
Angelscript: Error: BlueprintOverride method Initialize in class UFoo
  does not exist in superclass GameInstanceSubsystem, or is not a
  BlueprintImplementableEvent or BlueprintNativeEvent in C++.
```

Switch the parent class — keep the override method names — and the error clears.

Canonical pattern (from https://angelscript.hazelight.se/scripting/subsystems/):

```as
class UMyWorldSubsystem : UScriptWorldSubsystem
{
    UFUNCTION(BlueprintOverride)
    void Initialize()      // param-less; AS resolves to BP_Initialize
    {
        Print("MyGame World Subsystem Initialized!");
    }
}
```

> **Misleading-comment warning.** Some legacy AS code carries an inline comment claiming a "transparent substitution" from `UGameInstanceSubsystem` to the script wrapper handled by the preprocessor. **There is no such substitution** — the preprocessor at `Engine/Plugins/Angelscript/Source/AngelscriptCode/Private/Preprocessor/AngelscriptPreprocessor.cpp:1003-1014` only auto-generates the parameterless `Get()` accessor for subsystem subclasses. Class inheritance must be the wrapper explicitly. Verify against the canonical Hazelight docs before trusting an inline comment that asserts a non-obvious engine behavior.

### Auto-generated `::Get()` — parameterless for engine/game-instance/world

> The AS binding layer **auto-generates** `::Get(...)` for subsystem classes. **Do not declare it yourself** — AS rejects user-declared static member functions. The signature depends on subsystem kind (verified against `Engine/Plugins/Angelscript/Source/AngelscriptCode/Private/Binds/Bind_Subsystems.cpp:55-122`):

| Subsystem kind | Auto-generated `Get` signature | Caller |
|---|---|---|
| `UScriptEngineSubsystem` | `Get()` — no args | `UMyEngineSub::Get()` |
| `UScriptGameInstanceSubsystem` | `Get()` — no args (world context implicit via `FAngelscriptManager::CurrentWorldContext`) | `UMyGameInstanceSub::Get()` |
| `UScriptWorldSubsystem` | `Get()` — no args (world context implicit) | `UMyWorldSub::Get()` |
| `UScriptLocalPlayerSubsystem` | `Get(ULocalPlayer)` AND `Get(APlayerController)` overloads | `UMyPlayerSub::Get(LocalPlayer)` |

> **CRITICAL gotcha.** For game-instance / world / engine subsystems the accessor is **PARAMETERLESS**. Calling `UEventBus::Get(this)` from an Actor or Subsystem fails to compile:
>
> ```
> No matching signatures to 'UEventBus::Get(ABackyardGameMode)'
>   Calling function:
>   UEventBus Get()
> ```
>
> The compiler hint "`UEventBus Get()`" tells you the only available signature. Drop the arg.

```as
// ✅ RIGHT — UScriptGameInstanceSubsystem parent, no Get() declaration, param-less Initialize
class UEventBus : UScriptGameInstanceSubsystem
{
    UFUNCTION(BlueprintOverride)
    void Initialize() { /* setup */ }

    UFUNCTION(BlueprintOverride)
    void Deinitialize() { /* teardown */ }

    UFUNCTION(BlueprintCallable)
    void Subscribe(FName EventType, FCozyEventDelegate Callback) { /* ... */ }
}

// Caller-side — game-instance / world / engine: parameterless
UEventBus Bus = UEventBus::Get();   // ← no args

// LocalPlayer subsystems are the exception — they take a ULocalPlayer or APlayerController
UMyPlayerSub PlayerSub = UMyPlayerSub::Get(PlayerController);
```

Subsystem types and their lifetimes:
- `UScriptEngineSubsystem` — engine lifetime; survives map travel and PIE
- `UScriptGameInstanceSubsystem` — game-instance lifetime; one per running app
- `UScriptWorldSubsystem` — world lifetime; instantiated per loaded world
- `UScriptLocalPlayerSubsystem` — per local player
- `UScriptEditorSubsystem` — editor lifetime (editor-only builds)

### Origin

The "must inherit from the script wrapper" rule was diagnosed on 2026-04-30 during Cozy AS Day-2 work. Four AS subsystems (UEventBus, UTimeService, URNGService, USaveGameService) all failed `BlueprintOverride` on `Initialize`/`Deinitialize` because they inherited from the bare engine classes. Switching to `UScriptGameInstanceSubsystem` (with override names unchanged) cleared all 8 errors — `==script reload total == 79.335 ms` with zero residuals. Encoded here so future AS work doesn't rediscover.

## Function library namespaces (UClass → stripped)

`UBlueprintFunctionLibrary` subclasses are exposed in AS under a **stripped class name**. The leading `U` is dropped, and a configured suffix list strips trailing tokens. The defaults are at `Engine/Plugins/Angelscript/Source/AngelscriptCode/Public/AngelscriptSettings.h` lines 120–135:

```cpp
BlueprintLibraryNamespacePrefixesToStrip = { "UKismet", "UBlueprint" };
BlueprintLibraryNamespaceSuffixesToStrip = {
    "Statics", "Library", "BlueprintLibrary",
    "BlueprintFunctionLibrary", "FunctionLibrary"
};
```

Strip is sorted by length (longest match wins). Common results:

| C++ class | AS namespace | Example call |
|---|---|---|
| `UGameplayStatics` | `Gameplay::` | `Gameplay::DoesSaveGameExist("Default", 0)` |
| `UKismetMathLibrary` | `Math::` | `Math::Clamp(x, 0.0, 1.0)` |
| `UKismetSystemLibrary` | `System::` | `System::SetTimer(this, n"Tick", 1.0, true)` |
| `UGameplayTagsManager` | `Gameplay::` (note: collision — check) | (rare; usually accessed via gameplay tags directly) |

**Calling `UGameplayStatics::*Foo` directly from AS will NOT resolve** — AS sees the symbol as ambiguous or missing and produces misleading "no matching signatures" errors. Always use the stripped namespace.

### Save-game functions (canonical AS forms)

```as
Gameplay::DoesSaveGameExist("Default", 0)              // bool
Gameplay::DeleteGameInSlot("Default", 0)               // bool
Gameplay::SaveGameToSlot(SaveObj, "Default", 0)        // bool
Gameplay::LoadGameFromSlot("Default", 0)               // returns USaveGame*
```

String literals autobind to `FString`; `0` autobinds to `int32`. The "(const FString, const int)" / "(FString, int&)" error variations seen when calling these via the wrong namespace are AS picking up nearest-name candidates from elsewhere — not signature-arity issues. Once the namespace is correct, the literals match.

### WorldContext auto-fill

UFUNCTIONs marked `meta = (WorldContext = "WorldContextObject")` get the world-context parameter auto-filled by AS. The auto-fill source is `FAngelscriptManager::CurrentWorldContext` (see `Bind_AActor.cpp:226`, `Bind_Logging.cpp:176`). Drop the world-context arg in AS:

```as
AGameModeBase GameMode = Gameplay::GetGameMode();      // canonical — no args
// fallback if AS rejects no-arg form for some reason:
AGameModeBase GameMode = Gameplay::GetGameMode(this);
```

`UKismetSystemLibrary::PrintString(WorldContextObject, ...)` similarly becomes `System::PrintString(...)` with the context auto-filled.

### Origin

This rule was diagnosed live during 2026-04-30 Cozy AS Day-2 work. Five different argument patterns (`("Default", 0)`, `("Default", int32(0))`, local vars, member fields, `private const`) all failed against `UGameplayStatics::*` — symptom was the `(const FString, const int)` mismatch error. Root cause was the wrong class qualifier; `Gameplay::*` resolved cleanly. Encoded here so future AS work doesn't rediscover.

## Networking

- RPC functions **default to reliable** (C++ defaults to unreliable). Mark `Unreliable` explicitly when needed
- Actor replication: `default bReplicates = true;`
- Property replication: `UPROPERTY(Replicated)` or `UPROPERTY(ReplicatedUsing = OnRep_MyProp)`
- Replication conditions: `OwnerOnly`, `SkipOwner`, `InitialOnly`, etc.

```as
class ANetworkedActor : AActor
{
    default bReplicates = true;

    UPROPERTY(Replicated)
    int SyncedValue = 0;

    UFUNCTION(Server)
    void ServerUpdateValue(int NewValue) { SyncedValue = NewValue; }

    UFUNCTION(NetMulticast, Unreliable)
    void MulticastEffect() { /* play VFX on all clients */ }
}
```

## Hot-reload behavior

- Saving an `.as` file with the AS plugin enabled triggers a hot recompile
- **Script-only methods** (no `UFUNCTION`) reload fastest — no UE reflection update
- **UFUNCTION changes** require a heavier reload (updates Blueprint graph)
- **Struct property changes** require a full reload (any property, even non-UPROPERTY)
- **New classes** appear after reload — no editor restart needed
- Compile errors block hot reload; the previously-compiled version remains active until the error is fixed
- Hot reload is editor-only. Packaged builds compile AS to its final form at cook time

**Best practice:** Keep performance-critical inner loops as script-only methods. Use `UFUNCTION()` only at the Blueprint boundary.

## Common pitfalls

- **`Super::Method()` syntax** — AS does not provide a `Super` namespace. Just override the method body; parent invocation is implicit through the BP call graph.
- **Forgetting `UFUNCTION` on a method called from BP / delegate / timer** — invisible to UE reflection; binding/dispatch fails silently or at compile time.
- **`UPROPERTY()` missing on UObject reference field** — UE's GC will not track the reference; the object can be garbage-collected unexpectedly.
- **Direct `Execute()` on potentially-unbound delegate** — crashes if unbound. Use `ExecuteIfBound` for single-cast or `Broadcast` for multi-cast.
- **Returning a local UObject without tracking** — `NewObject` requires the caller to keep a reference; otherwise GC reclaims.
- **Forgetting `WorldContextObject` parameter** — many UE static helpers (`GetGameInstance`, `GetPlayerController`, etc.) need a world context. Pass `this` from an actor/component or `GetWorld()`.
- **`BlueprintPure` on a side-effecting function** — pure nodes execute every time their output is read; hidden side effects accumulate.
- **Using `TArray` indexing without bounds check** — `arr[i]` on out-of-range crashes. Use `arr.IsValidIndex(i)`.
- **Subsystem `Initialize` doing heavy work** — runs at engine/game-instance startup. Defer heavy setup to lazy-init or a separate `Start()` method.
- **Replicated property without `UPROPERTY(Replicated)`** — value never crosses the wire even if the class is replicated.
- **Hot reload after class rename** — subsystem state lost; old subscribers point to the dead class. Restart editor after structural changes.

## BP↔AS interop boundary

- Logic that needs strong typing, refactor-safety, version-controlled implementation → AS
- Logic that benefits from designer iteration in the editor (visuals, BP event graphs, content authoring) → BP, calling AS-defined classes/methods
- Data-only assets (Curves, DataTables, Datasets) → still BP-side; AS reads them via `UFUNCTION(BlueprintCallable)` getters
- Don't reimplement BP-native helpers in AS unless you need cross-platform AS testing — use the BP nodes via AS's UE-binding layer

## Performance notes

- AS function-call overhead is higher than C++ but lower than BP. For per-frame hot paths, prefer C++ if the engine version supports mixed AS+C++; otherwise keep AS hot paths simple and avoid `TMap` lookups in tick
- AS `TArray` operations are the same cost as C++ TArray operations
- Delegate broadcast cost scales linearly with subscribers. Snapshot-iterate to allow safe Unsubscribe during dispatch (see EventBus reference implementation)
